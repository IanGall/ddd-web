# ADR 0004: 唯一主题源、暗色模式接线与主题防护

## 状态

已采纳（日期：2026-09-16）

## 背景

在从 Ant Design 迁移前，项目使用 `src/theme/` 目录下的 Ant Design 主题配置套件驱动样式。随着迁移完成，旧有的 `ThemeConfig` 三件套已整体删除。
项目全面采用 Tailwind CSS v4 与 shadcn/ui，需要确立全仓唯一的样式与主题来源，建立严密的暗色模式渲染管线，并解决 CSS 变量在自动化门禁中极易漏检导致的样式事故问题。

## 决策

### 1. 唯一主题源与结构构成

- **唯一主题源为 `src/index.css`**（彻底摒弃 `src/theme/` 目录），由四部分构成：
  1. **三条核心样式引用**：`@import 'tailwindcss';`、`@import 'tw-animate-css';`、`@import 'shadcn/tailwind.css';`；
  2. **`:root` 与 `.dark` OKLCH 变量定义**：基于 shadcn 官方 neutral 调色板声明全套设计 token（含基础色、边框、环、卡片与侧栏色彩，以及圆角 `--radius`）；
  3. **`@theme inline` 主题映射块**：建立 CSS 变量到 Tailwind 类名的直接映射；
  4. **`@layer base` 全局基底样式**：全局重置 html、body、#root 的高宽与背景色。

### 2. `@theme inline` 映射块必须自主维护

- `shadcn/tailwind.css` 仅提供针对组件的 `data-*` 变体与基础 `@utility` 类，**其本身不包含任何颜色映射**。
- 必须在 `src/index.css` 的 `@theme inline` 块中显式维护 `--color-*` 映射（如 `--color-background: var(--background);`、`--color-foreground: var(--foreground);` 等）。若删除该块，全站的 `bg-background`、`text-foreground`、`border-border` 等类名将全部失效。

### 3. 保留 `@custom-variant dark (&:is(.dark *));`

- Tailwind CSS v4 的 `dark:` 变体在默认情况下基于操作系统媒体查询 `prefers-color-scheme`。
- 如果不将其显式重写为基于 `.dark` 类名选择器的类变体，当用户的操作系统处于深色模式、但在应用内选择了浅色模式时，`dark:` 工具类依然会被触发，而 `:root` 变量仍为浅色值，导致深色类与浅色变量交织，产生严重的「半深半浅」界面错乱。

### 4. 变量完整性自动化守卫与真实事故防范

- 设立 `src/test/theme-vars.test.ts` 结合 `src/test/fixtures/neutral-inline-colors.light.json` 作为主题变量防回归守卫。快照取材自 shadcn 官方注册表 `colors/neutral.json` 的 `inlineColors`（`:root` 32 个变量含 `radius`，`.dark` 31 个变量不含 `radius`）。
- **防范的真实事故**：在前期迁移中，`:root` 曾漏声明 `--radius`，导致 `@theme inline` 中的 `--radius-lg: var(--radius)` 计算值为空，**全站按钮、输入框、卡片圆角瞬间全部归零**。然而当时 189 个单元测试全绿、`pnpm build` 也顺利通过——因为 vitest 的 jsdom 环境不加载 Tailwind 插件，且编译器无法校验 CSS 运行时取值。本守卫单测直接分析 CSS 源码变量集合，一旦漏变量立即中断 CI。后续调整变量必须同步更新快照。

### 5. 暗色模式接线与 SPA 首帧防闪烁

- **Provider 树接线**：在 `src/App.tsx` 中引入 `next-themes@0.4.6` 的 `ThemeProvider`，配置属性为 `attribute="class"`、`defaultTheme="system"`、`enableSystem`、`storageKey={THEME_STORAGE_KEY}`、`disableTransitionOnChange` 与 `enableColorScheme`。Provider 严格置于 `QueryClientProvider` 与 `TooltipProvider` 之间。
- **通知组件 `Toaster`（sonner）主题同步**：在 `App.tsx` 中通过 `ThemedToaster` 包装组件根据 `resolvedTheme` 显式传入 `<Toaster theme={resolvedTheme === 'dark' ? 'dark' : 'light'} />`。**坚决不改动生成物 `src/components/ui/sonner.tsx`**——因为该生成物组件内部的代码结构为 `theme={...} ... {...props}`，外部传入的 `theme` 会在最后展开并成功覆盖内部默认值。
- **SPA 防闪烁内联脚本必须手写**：
  - `next-themes` 自带的脚本注入机制依赖 React 挂载阶段，在纯客户端单页应用（SPA）中是在**首帧渲染之后**才被执行，根本无法阻止用户在深色模式下先白后黑的「白色闪烁」（该注入特性原本针对 Next.js SSR 设计）；且其 `scriptProps` 只能增补属性，无法禁用其注入行为；
  - 因此在 `index.html` 的 `<head>` 模块入口前手写一段同步执行的自执行内联脚本，直接读取 `localStorage.getItem('ddd-web-theme')` 并即时变更 `document.documentElement` 的 class 与 `colorScheme`；
  - **同步约束**：该内联脚本硬编码的 key `'ddd-web-theme'` 必须与 `src/lib/theme.ts` 的 `THEME_STORAGE_KEY` 严格保持手工同步（HTML 内联脚本无法执行 ES Module 的 import）。

### 6. 刻意偏离官方注册表：暗色侧栏主色中性化

- 在 `src/index.css` 的 `.dark` 块中，覆写 `--sidebar-primary: oklch(0.922 0 0)` **并且同时**覆写 `--sidebar-primary-foreground: oklch(0.205 0 0)`。
- **偏离原因**：官方 neutral 注册表中 dark 的 `--sidebar-primary` 默认给的是紫色 `oklch(0.488 0.243 264.376)`，会使暗色模式下侧栏顶部的品牌块 Logo 背景与底部用户头像异常泛紫，违背了中性色调的设计要求；如果只把主色改为高亮浅灰而漏改前景色，由于官方暗色前景是近白色的 `oklch(0.985 0 0)`，会造成「浅灰底配白字」（白底白字）的不可读灾难。因此两项必须成对覆写。改回默认前需充分评估此处的对比度。

### 7. 数据强调色板与十六进制红线豁免

- `src/lib/palette.ts` 是全仓**唯一允许出现十六进制颜色字面量**的文件（`scripts/check-style.sh` 第 6 条红线将该文件与 `src/test/` 单元测试目录列为显式豁免项）。
- 调色板定义 `DATA_PALETTE`，包含 orange, teal, navy, amber 四色，提供 light/dark 双值色彩映射，并通过 `resolveDataAccent(accent, mode)` 解析。
- **对比度与色相守卫**：暗色值对暗色背景 `#171717` 的对比度实测为 7.71、10.28、8.00、11.35（均超过 WCAG AA 标准的 4.5:1 要求），且暗色与浅色值的色相差严格控制在 20° 以内（确保同色系）。任何对调色板的修改都受到 `src/test/palette.test.ts` 自动化断言的守护。

## 理由

- 确立清晰的主题单一真相源（SSOT），消除样式多头管理的技术债务。
- 构建涵盖类型、单测、Lint 与真实 DOM 渲染的多层防护，确保无死角拦截样式与闪烁缺陷。

## 后果（含代价与已知偏离）

- **代价 1：双处硬编码存储键风险**：`index.html` 无法 import 常量，未来若变更 `THEME_STORAGE_KEY` 必须同时手动修改 `index.html` 中的 `'ddd-web-theme'` 字符串。
- **代价 2：样式修改测试强耦合**：修改 `src/index.css` 中的 token 集合会导致 `theme-vars.test.ts` 门禁变红，维护者必须手动更新 `src/test/fixtures/neutral-inline-colors.light.json` 快照。
- **已知偏离**：
  - `.dark` 下成对覆写了 `--sidebar-primary` 与 `--sidebar-primary-foreground`，脱离了官方 neutral 注册表的紫色默认值；
  - `src/lib/palette.ts` 保留了受控的十六进制颜色字面量用于数据强调可视化。
